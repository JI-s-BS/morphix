# Afinia QD330 / UP-family: protocol notes

Notes for developers working on the Afinia QD330 support in
[packages/printer/src](../packages/printer/src) and the `.gx` writer in
[packages/slicing/src](../packages/slicing/src). The QD330 speaks a FlashForge-style TCP
protocol. Facts below are marked **verified** only where they were checked on a real QD330
(firmware v2.1.3); everything else is a guess from FlashForge-family clients or community
reverse engineering. The safety model and the operator checklists live in
[SAFETY.md](SAFETY.md); this page links to them by step ID instead of repeating them.

The catalog entry is `afinia-qd330` ([printers.ts](../packages/catalog/src/printers.ts)):
220 × 220 × 220 mm, origin at the bed centre, 0.4 mm nozzle, 1.75 mm filament, `.gx` files,
limits 250 °C nozzle / 100 °C bed. The build volume comes from the printer's M115 report and is
not confirmed against the official spec.

| File | What it holds |
|---|---|
| [index.ts](../packages/printer/src/index.ts) | `TcpTransport` and `PrinterObserver`: read-only polling |
| [protocol.ts](../packages/printer/src/protocol.ts) | Framing, reply parsing, read-only allowlist, CRC-32, M661 list parser (pure) |
| [control.ts](../packages/printer/src/control.ts) | `QD330Controller`: job and machine control, disabled by default |
| [machine.ts](../packages/printer/src/machine.ts) | Command builders, hard limits, `allowUnverified` flags, the command table |
| [auth.ts](../packages/printer/src/auth.ts) | Print approval tokens |

## Connection and framing

- **TCP port 8899** on `<printer-ip>`. Default timeouts: connect 4 s, reply 5 s.
- **Commands** are sent as `~<CMD>\r\n`, e.g. `~M119\r\n`. A command containing `~`, `\r` or
  `\n` is rejected before it is sent. **Verified.**
- **Replies** start with `CMD <verb> Received.` and end with a line `ok`. A reply counts as
  acknowledged only if it echoes `Received`, ends in `ok` and contains no error word
  (`error|fail|refus|denied|invalid|crc`, with the file name blanked out first). **Verified** format.
- **Sessions.** Every batch is wrapped in `M601 S1` (take control, reply `Control Success V2.1.`)
  … `M602` (release, reply `Control Release.`). **Verified.** M601 has no physical effect.
- **No login.** Morphix sends no credentials; the M601 session is a lock, not authentication.
  Approval for printing is Morphix's own layer ([auth.ts](../packages/printer/src/auth.ts),
  [SAFETY.md](SAFETY.md#approval-before-every-print)).
- **One at a time.** All status polls and control sessions go through one queue in the
  controller (`controller.transport` is the read-only transport that shares it). Whether the
  printer accepts a second control connection is **unknown**; Morphix never opens two.
- **Stale lock.** On the real printer, after a print was stopped, M601 answered `Control failed.`
  for 18 minutes with no other client connected, and an M602 from any connection cleared it. When
  M601 fails and none of Morphix's own sessions is open, the controller sends M602, asks once
  more, and logs a `recoverControl` entry. The `Control failed.` wording in the fake printer is
  marked unverified.

## Commands

The observer can only send the read-only allowlist: `M601 S1`, `M602`, `M115`, `M119`,
`M105`, `M114`, `M27`. Anything else is rejected before it reaches the socket.
The controller builds every other command from a fixed table (`COMMAND_SPECS` in
[machine.ts](../packages/printer/src/machine.ts)); there is no raw G-code method.

| Method | Command(s) | State rule | Confirmed when | On hardware |
|---|---|---|---|---|
| `readStatus()` | M119 M105 M114 M27 | any | read-only | verified |
| `readInfo()` | M115 | any | info parsed | verified |
| `listFiles()` | M661 | any | binary list parsed | verified |
| `uploadFile()` | M28, raw bytes, M29 | READY | file appears in M661 | verified for a single packet only |
| `startPrint()` | `M23 0:/user/<name>` | READY, file listed | `BUILDING_FROM_SD` and `CurrentFile` matches | status change verified; a real `.gx` printing to completion **unverified** |
| `pause()` | M25 | printing | paused status (see below) | **unverified** |
| `resume()` | M24 | paused, same file | `BUILDING_FROM_SD` and not paused | **unverified** |
| `cancel()` | M26 | any | READY | verified |
| `home()` | G28 | READY, not moving | M114 at 110/110/220 (±0.5 mm), not MOVING | verified (reply timing unknown; 60 s timeout) |
| `setLight()` | `M146 r<r> g<g> b<b> F0` | any | M119 `LED:` matches on/off | **unverified** (Adventurer syntax) |
| `setFan()` | `M106 S<0-255>` / `M107` | any | never (no read-back) | **unverified** |
| `setNozzleTemp()` | `M104 S<c> T0` | READY to heat; not printing to cool | M105 `T0` target | **unverified** |
| `setBedTemp()` | `M140 S<c>` | as above | M105 `B` target | **unverified** |
| `coolDown()` | `M104 S0 T0`, `M140 S0` | not printing | both targets 0 | **unverified** |
| `motorsOff()` | M18 | READY, not moving | never (no read-back) | **unverified** |
| `emergencyStop()` | [M112], M26, `M104 S0 T0`, `M140 S0` | any | READY, both targets 0 | M26 verified; M112 **unverified** |

G1 moves over the network are accepted but ignored, so Morphix offers no jog controls. Whether
M26 clears the heater targets is **unknown** (emergency stop sends M104/M140 S0 anyway).
Unverified commands need their `allowUnverified` flag (checklist M2–M5, M8 in
[SAFETY.md](SAFETY.md#machine-controls-checklist)).

## Status fields

Reply bodies as recorded from the real printer (the fake printer reproduces them):

| Command | Lines | Parsed into |
|---|---|---|
| M115 | `Machine Type: Afinia 3D QD330`, `Machine Name:`, `Firmware: v2.1.3`, `SN:`, `X: 220 Y: 220 Z: 220`, `Tool Count: 1` | `PrinterInfo` |
| M119 | `Endstop: …`, `MachineStatus: READY`, `MoveMode: READY`, `Status: S:1 L:0 J:0 F:0`, `LED: 1`, `CurrentFile: …` | `machine`, `moveMode`, `currentFile` |
| M105 | `T0:<cur>/<target> T1:0.0/0.0 B:<cur>/<target>` | nozzle and bed current/target |
| M114 | `X:110.000 Y:110.000 Z:220.000 A:0.000 B:0` | position |
| M27 | `SD printing byte <n>/<total>`, `Layer: <a>/<b>` | progress %, layer |

- **`MachineStatus`**: `READY` when idle, `BUILDING_FROM_SD` while printing a stored file.
  Only M119 decides online/offline; a slow M105/M114/M27 reply (2.5 s limit) just leaves that
  field out.
- **`MoveMode`**: `READY`, `MOVING` (homing, printing), `PAUSED`.
- **`CurrentFile`** is compared by base name, with or without the `.gx` extension.
- Whether `Status: … F:` reflects the fan, and whether `LED:` follows M146, is **unverified**.
- Any `MachineStatus` the tracker does not know is reported as `unknownStatus`; no outcome is guessed.

## Pause behaviour

M25 pause and M24 resume are **unverified**, and so is the paused status string. The default
`pausedStatuses` is `["PAUSED"]` (set with `MORPHIX_PAUSED_STATUSES`). FlashForge-family firmware
can keep `MachineStatus: BUILDING_FROM_SD` while paused and only change `MoveMode` to `PAUSED`; the
code comments say the QD330 seems to do the same, so `isPausedStatus` treats either as paused.
The printer finishes queued moves before it pauses, so the pause confirmation waits up to 30 s.
What the heaters do while paused is unknown. Resume needs a fresh approval for the paused file.
Checklist steps 5 and 6 settle all of this.

## Printing a stored file

`M23 0:/user/<name>` (reply timeout 10 s) replies `File opened: <name> Size: <n>` / `File selected`.
When the caller passes `expectedBytes` and the reported size differs, the controller sends M26
and fails, so a partly written file is never printed. Start is confirmed when status shows
`BUILDING_FROM_SD` with the matching `CurrentFile` within 20 s. Completion is a heuristic (back to
READY with progress ≥ 99 or the last layer reached) until checklist step 4 records what M27 shows
at the end of a real print.

## Upload

1. Only when READY, and (unless `overwrite`) the name is not already stored.
2. `M28 <size> 0:/user/<name>` → `Writing to file: /data/<name>`. **Verified.**
3. Exactly `<size>` **raw bytes, no framing**, sent in 4 KB chunks (progress granularity only;
   optional `packetDelayMs` between chunks). Any unsolicited text is scanned for error words.
4. Wait 3 s (`uploadFlushDelayMs`, as FlashForge senders do), then `M29` (15 s timeout). A missing
   reply fails the upload.
5. Confirmed when the file appears in M661.

An earlier framed upload (16-byte header + padding to 4096 per packet) was wrong: the printer
stored the header as the start of the file, so jobs opened at 0 % and never heated, and the extra
bytes swallowed M29. Per-packet replies and error reporting during an upload are **unknown**.
[protocol.ts](../packages/printer/src/protocol.ts) keeps a standard CRC-32 helper (tested against
zlib), but the raw-byte upload sends no checksum. Multi-packet uploads still need checklist step 8.

**File names.** Uploads are sanitised to `[A-Za-z0-9._-]`, at most 64 characters, `.gx` only.
Plain `.g` needs `allowPlainGcode: true`; it stalled at 0 % on the real printer (with the old
framed upload). Files already on the printer, such as official Afinia files with spaces, pass
`assertStoredFileName`, which rejects `/ \ ~`, control characters and leading dots.

**M661 list** (binary): header `44 AA AA 44`, a big-endian u32 count, then per entry
`3A 3A A3 A3`, a big-endian u32 length and the UTF-8 path (e.g. `/data/<name>.gx`), optionally
followed by `ok`. The parser rejects more than 10 000 entries or names over 1024 bytes. **Verified.**

## The `.gx` container

From community reverse engineering of FlashForge FlashPrint output: the Cura plugin
`ronoaldo/FlashforgeFinderIntegration` (`plugins/GXWriter/gx.py`) and the Rust crate `xgcode`
agree on every offset. Morphix's code ([gx.ts](../packages/slicing/src/gx.ts)) was written from
the documented layout; no code was copied. Little-endian:

| Offset | Type | Field | Morphix writes |
|---|---|---|---|
| 0x00 | 12 B | magic `"xgcode 1.0\n\0"` | — |
| 0x0C | u32 | unknown | 0 |
| 0x10 | u32 | thumbnail offset | 58 |
| 0x14 / 0x18 | u32 | G-code offset (twice) | 14512 |
| 0x1C | u32 | print time (s) | from slicer |
| 0x20 / 0x24 | u32 | filament right/only, left (mm) | from slicer / 0 |
| 0x28 | u16 | multi-extruder type | **11** (community value, meaning unknown) |
| 0x2A | u16 | layer height (µm) | 200 |
| 0x2C | u16 | reserved | 0 |
| 0x2E | u16 | perimeter shells | 2 (or the perimeters used) |
| 0x30 | u16 | print speed (mm/s) | 60 |
| 0x32 / 0x34 / 0x36 | u16 | bed, extruder right, extruder left (°C) | from G-code / 0 |
| 0x38 | u16 | reserved | **1** (community value) |
| 0x3A | 14454 B | 80×60 24-bit BMP, bottom-up | grey render |
| 0x38B0 | … | G-code text to end of file | slicer output |

`readGx` follows the offsets in the header, so it reads files that differ from this layout.
`validateGx` checks magic, offsets, BMP size and format, that the G-code has moves, and that the
header values are plausible. `compareGxHeaders(ours, reference)` splits differences into
**structural** fields (offsets, unknown/reserved, multi-extruder type), which must match, and
**job** fields (time, filament, temperatures), which differ per print.

**Status:** round-trip and the community layout are verified by unit tests. Matching **Afinia**
QD330 output is **unverified** (`GX_LAYOUT_VERIFIED = false`): no official Afinia `.gx` has been
compared yet, nor the values at 0x28 and 0x38, the thumbnail style, or whether the printer needs
the header to match the G-code. The slicer profile
[qd330-pla-0.2mm.ini](../config/slicer-profiles/qd330-pla-0.2mm.ini) is also an unverified
guess: its start/end G-code is generic Marlin-style and most likely wrong for this firmware.
Sending generated `.gx` files stays blocked until `MORPHIX_GX_VERIFIED=1`.

## Validating against a real Afinia .gx

These steps only *read* a file; send nothing to the printer.

1. **Get an official file**: export one from the official Afinia slicer (note every setting
   used) or copy one already stored on the printer. Keep it outside the repo.
2. **Dump its header** from the repo root:
   ```bash
   node -e '
     const b = require("node:fs").readFileSync(process.argv[1]);
     console.log("magic", b.subarray(0, 12).toString("hex"), "size", b.length);
     for (const s of ["u32 0x0C","u32 0x10","u32 0x14","u32 0x18","u32 0x1C","u32 0x20","u32 0x24","u16 0x28","u16 0x2A","u16 0x2C","u16 0x2E","u16 0x30","u16 0x32","u16 0x34","u16 0x36","u16 0x38"]) {
       const [t, o] = s.split(" "), off = parseInt(o, 16);
       console.log(o, t === "u32" ? b.readUInt32LE(off) : b.readUInt16LE(off));
     }
     console.log(b.subarray(b.readUInt32LE(0x14), b.readUInt32LE(0x14) + 1500).toString("latin1"));
   ' /path/to/reference.gx
   ```
   or call `validateGx(ref)` and `readGx(ref).header` from `@morphix/slicing`.
3. **Check the structure.** Expect magic `78 67 63 6f 64 65 20 31 2e 30 0a 00` and offsets
   58 / 14512 / 14512. Note the values at 0x0C, 0x28, 0x2C and 0x38. If `validateGx(ref)` reports
   **errors**, the community layout is wrong for the QD330: stop and investigate.
4. **Compare with Morphix output** for the same model and settings: `compareGxHeaders(ourGx, ref)`.
   Resolve every `structural` difference (e.g. `multiExtruderType` / `reserved38` in `writeGx`).
5. **Compare the G-code preamble** (`referenceGcodeHead`, the first 2000 bytes): copy its start
   sequence (heating, homing, any FlashForge M-codes such as `M118`, `M601`, `M651`, `M132`), end
   sequence and comment header into the slicer profile's `start_gcode` / `end_gcode`. Check
   `M82`/`M83` and whether it uses G0. Look for its bed-leveling command (checklist L2).
6. **Thumbnail**: `decodeBmp24(readGx(ref).thumbnailBmp)`; check size, bit depth, grey or colour.
7. **Only then** consider a supervised test print of a small calibration cube (checklist steps 8–9).
   When it works, set `GX_LAYOUT_VERIFIED` / `QD330_PLA_DEFAULTS.verified` and update this page.

## Bed leveling

The Afinia QD330 User Guide (01-12-2024, §5.1 and Q&A Q3/Q5) describes one-click auto leveling
run by the printer's firmware, says it defaults to leveling before each print, and that
"automatic leveling before printing" can be switched on in the printer's settings. It names no
G-code. **Morphix has no verified leveling command** ([leveling.ts](../packages/slicing/src/leveling.ts)).

- **Default (`gcode` mode, unverified):** every print gets `G29` at the `;MORPHIX_LEVEL_BED`
  marker in the start G-code (after homing with the bed hot, before the nozzle heats and primes),
  then `G1 Z10`. Without the marker it goes right after the first `G28`, with a warning.
- **`MORPHIX_LEVEL_GCODE`** replaces `G29` with up to 4 commands separated by `;`. Commands that
  move, heat, extrude, control jobs, write files or change the firmware are refused; a refused
  value falls back to `G29` and is logged.
- **`MORPHIX_LEVELING=printer`** adds nothing and leaves leveling to the printer's own setting.

Run checklists L1 and L2 in [SAFETY.md](SAFETY.md#bed-leveling-checklist-qd330).

## Fake printer for tests

`FakeQD330` ([fake-server.ts](../packages/printer/src/fake-server.ts)) listens on `127.0.0.1`
only and reproduces the recorded reply formats, the binary M661 list, raw-byte uploads, and the
M23/M25/M24/M26 state changes. It also emulates G28 (MoveMode MOVING, then 110/110/220), M146
(`LED:`), M106/M107, M104/M140 targets that heat and cool over time, M18 and M112. Error wordings,
the paused status and other guesses are marked `UNVERIFIED` in the source.

```ts
const fake = new FakeQD330({ files: { "cube.gx": buf }, pausedStatus: "PAUSED", pauseViaMoveMode: true,
  failures: { staleControlLock: true, silent: ["M23"], dropOn: ["M26"], rejectUpload: true, ignorePause: true } });
const port = await fake.listen();
fake.setProgress(45, [45, 100]); fake.finishPrint();
fake.received; fake.uploads; fake.controlConflicts;
await fake.close();
```

Other options: `stateChangeDelayMs`, `m661Ok`, `homeDurationMs`, `heatRatePerSec` /
`coolRatePerSec`, `printTargets`, `cancelClearsTargets`, and failures such as `refuseControl`,
`corruptUpload`, `dropOnPacket`, `loseUploadedFile`, `ignoreStart|Resume|Cancel|Home|Light|Fan|Temps|Motors`,
`rejectVerbs`, `noLedInM119`, `dropAfterM112`. Tests are in `tests/phase5-*.test.ts` and
`tests/printer-control-*.test.ts`; [tests/phase5-helpers.ts](../tests/phase5-helpers.ts) patches
`Socket.connect` so any host other than `127.0.0.1` / `localhost` fails the test.
